# adapty-mcp

A Model Context Protocol (MCP) server that exposes the full public Adapty REST API surface as tools — Server-Side API v2 (12 tools), legacy v1 (7 tools), Web API (3 tools), Analytics Export (3 tools), and webhook utilities (2 tools). 27 tools total.

## Quick start

Install globally:

```sh
npm i -g adapty-mcp
```

Run as an MCP stdio server (any MCP-compatible client can spawn it):

```sh
ADAPTY_SECRET_API_KEY=secret_live_... adapty-mcp
```

For Cursor or any other MCP client, point its server config at the `adapty-mcp` binary and pass `ADAPTY_SECRET_API_KEY` via env. Optional: `ADAPTY_PUBLIC_API_KEY` for Web API tools, `ADAPTY_SECRET_API_KEY_SANDBOX` / `ADAPTY_PUBLIC_API_KEY_SANDBOX` for the Adapty staging environment.

## Multi-app config

If you manage multiple Adapty apps from the same machine, write `~/.config/adapty-mcp/accounts.json`:

```json
{
  "default": "main",
  "apps": {
    "main": {
      "live":    { "secretKey": "secret_live_main...",  "publicKey": "public_live_main..." },
      "sandbox": { "secretKey": "secret_stag_main...",  "publicKey": "public_stag_main..." }
    },
    "side-project": {
      "live": { "secretKey": "secret_live_side..." }
    }
  }
}
```

Override the path with `ADAPTY_MCP_CONFIG=/path/to/accounts.json`.

Each tool accepts optional `app` and `environment` arguments:

- `app` — name from the `apps` map. Omit to use `default`.
- `environment` — `"live"` (default) or `"sandbox"`.

When the config file is present, env-var fallbacks are NOT consulted, so multi-app setups behave predictably. The file mode is checked at startup; loose permissions trigger a stderr warning recommending `chmod 600`.

Set `ADAPTY_HTTP_TIMEOUT_MS` to override the default 30-second timeout. Set `ADAPTY_MCP_DEBUG=1` to include redacted body excerpts in error logs.

## Tool catalog

(generated by `npx tsx scripts/gen-tool-docs.ts`)

### Server-Side API v2

| Tool | Description |
| --- | --- |
| `adapty_profile_get` | Retrieve an Adapty user profile (access levels, subscriptions, non-subscriptions). Use case: check whether a customer currently has an active access level. |
| `adapty_profile_create` | Create a new Adapty profile. Use case: pre-create a profile when your backend signs up a user. |
| `adapty_profile_update` | Update Adapty profile attributes (name, email, custom_attributes, ...). Use case: sync user profile changes from your backend. |
| `adapty_profile_delete` | Delete an Adapty profile and its data. Use case: GDPR/CCPA delete request. |
| `adapty_access_level_grant` | Grant or extend an access level for a customer (without an actual purchase). Use case: comp a creator account, refund credit. |
| `adapty_access_level_revoke` | Revoke a previously granted access level. Use case: undo a manual grant. |
| `adapty_transaction_set` | Submit a store transaction (App Store or Google Play) for Adapty to verify and record. Use case: server-side receipt validation when your client cannot reach Adapty directly. |
| `adapty_stripe_purchase_validate` | Validate a Stripe subscription/customer with Adapty. Use case: granting access on Stripe purchase events. |
| `adapty_integration_identifiers_set` | Attach external integration identifiers (Amplitude, Mixpanel, AppsFlyer, etc.) to an Adapty profile so server-to-server analytics can correlate the same user across systems. |
| `adapty_paywall_get` | Fetch a single paywall by its developer ID. Use case: server-side rendering of a paywall configuration. |
| `adapty_paywalls_list` | List all paywalls configured for the current Adapty app. Use case: build a server-side index of paywall keys. |
| `adapty_paywall_update` | Update a paywall configuration (name, remote_config, products). Use case: rotate remote config or product list from a server-side admin tool. |

| Tool | Description |
| --- | --- |
